# 局域网掼蛋 (LAN GuanDan)

一个基于 Node.js、React 和 Socket.IO 开发的局域网联机掼蛋游戏。支持 4 人（2v2）与 3 人（争上游）两种玩法，普通与技能两种模式，开箱即用。

## ✨ 特色功能 (Features)

### 🎮 核心体验
- **局域网联机**：无需外网，同一个 Wi-Fi 下即可畅玩。
- **智能 AI 托管 (Bot AI)**：人数不足时，智能 Bot 自动补位；采用多层级决策引擎，含阶段感知、组牌优化、炸弹决策矩阵、终局保护、抢头游、送队友、联盟配合等策略。
- **完整对局系统 (Match System)**：
  - 从 **2 打到 A** 的完整对局流程，自动管理多局游戏。
  - 每局结束后 **自动开始下一局**。
  - 对局结束条件：某队（4 人）或某玩家（3 人）达到 A 级别并 **连胜 2 次**。
- **两种人数模式**：
  - **4 人模式**：2v2 对抗，标准两副牌 108 张，每人 27 张。
  - **3 人模式**：各打各的争上游，去掉一种花色后共 81 张牌，每人 27 张，最大炸弹为「三王炸」。
- **完整规则实现**：
  - 支持 **进贡/还贡**（包括双扣双贡、单扣单贡）。
  - 支持 **抗贡**（双大王在手免贡）。
  - 支持 **接风**（4 人模式下队友走牌后接风）。
  - 支持 **升级**（从 2 打到 A；4 人双扣升 3 级、单扣升 2 级、保级升 1 级；3 人头游升 3 级、二游升 1 级）。
  - 支持 **同花顺**（炸弹级资源，含逢人配补缺识别）。
  - 支持 **三王炸**（3 人模式最大炸弹）。
- **红心级牌万能牌 (Wild Card)**：
  - 红心级牌可作为万能牌使用。
  - 选牌时自动识别所有可能的牌型组合。
  - 多种可能时弹出选择界面，由玩家决定。
- **复盘记录 (Game Replay)**：
  - 每局自动落盘完整记录（含四家初始手牌、每手出牌及剩余手牌）。
  - 保存为 JSON，可还原任意时刻牌面，方便复盘 BOT 决策。

### 🎯 技能掼蛋模式 (Skill Mode)
- **技能卡系统**：每局开始时每位玩家随机获得 **2 张技能卡**。
- **5 种技能卡**：
  - **无中生有**：获得 2 张随机牌。
  - **顺手牵羊**：从目标玩家随机获得 1 张牌。
  - **过河拆桥**：让目标玩家随机弃 1 张牌。
  - **乐不思蜀**：让目标玩家下回合跳过（无法出牌和使用技能）。
  - **五谷丰登**：所有未出完的玩家各获得 1 张随机牌。
- **使用规则**：
  - 只能在自己的回合使用技能。
  - 每张技能卡只能使用一次。
  - 使用技能后仍可正常出牌。
  - 新获得的牌会短暂高亮显示。
- **智能 Bot**：Bot 会根据局势智能使用技能卡。

### 🖥️ 界面与交互
- **摸鱼模式 (Stealth Mode)**：按 **`i`** 键一键切换至 **伪装 VS Code 界面**，完美融入办公环境。
- **智能理牌 (Smart Sort)**：提供「同花顺视图」，同点数牌纵向堆叠、同花顺高亮显示，支持一键切换回普通视图。
- **自由选座**：游戏开始前点击空座位即可换座。
- **房间聊天**：内置实时聊天框，支持文字和 Emoji，消息以气泡显示；Bot 也会发送 Emoji 表情。
- **房间列表**：查看所有活跃房间，快速加入游戏。
- **房主控制**：房主可强制结束对局、切换游戏模式（普通/技能）、切换人数（3 人/4 人）。

## 🤖 Bot AI — 智能决策引擎

Bot AI 采用**多层级策略系统**，模拟人类掼蛋高手的决策方式。

### 组牌优化 (Hand Planning)
- 主动识别所有牌型：单张、对子、三条、三带二、顺子、**连对（木板顺子，如 22/33/44）**、钢板、炸弹、同花顺、四大天王、三王炸。
- 同花顺识别含**逢人配补缺**，并严格校验「5 张都是独立牌张」，杜绝一张级牌被重复使用。

### 阶段感知 (Phase Awareness)
| 阶段 | 策略 |
|------|------|
| **开局** (>20 张) | 情况不明对子先行，探路不暴露最弱牌 |
| **中期** (10-20 张) | 逐轮出最弱组合，保留强牌控盘 |
| **残局** (≤10 张) | 计算对手剩余牌数，实施终局保护与冲刺 |

### 抢头游与配合
- **抢头游冲刺**：手牌 ≤3 手且全是硬牌时，主动领硬牌冲刺，不等对手先走。
- **送队友走头游**：队友剩 ≤5 张时抬牌送队友，避免自己冲不动还干等。
- **抗贡避单张**：对手握双大王时，优先出可控牌型（对子/顺子/连对/三带二）而非单张。
- **终局保护**：下家敌人剩 1 张 → 不出单张；下家敌人濒走 → 优先非单张组合。

### 炸弹决策 (Bomb Decision)
- **廉价目标不炸**：对手出单张/对子时，除非自己冲刺收尾或下家只剩 1 张，否则一律不炸——花 4~5 张核心资源只换回对手 1~2 张不划算。
- **主动领炸收紧**：只有「对手全濒走」或「出完这颗炸能走完」时才主动领炸，且领最小的炸。
- **6 炸/天王炸留底**：超强控制资源只用于压炸、阻断成型牌、以炸压炸，不主动甩。
- **同花顺保护**：同花顺是炸弹级资源，绝不拆出单张去跟牌。
- **枪不打四**：对家剩 4 张非炸弹不炸（但自己全是炸弹或握 5+ 张大炸时破例）。

### 角色定位
- **主攻手**（牌力 ≥40）：当仁不让，力争头游。
- **助攻手**（牌力 ≤20）：只出小牌，不抢控制，全力助队友。
- 联盟出牌永不炸；联盟走牌自动过牌不压。

## 🚀 快速开始 (Quick Start)

### 方式 1: 直接运行 (Windows 本地)
1. 下载最新的 `guandan-game.exe`。
2. 双击运行，自动启动服务器（默认端口 3000）。
3. **房主**：浏览器打开 `http://localhost:3000` 或本机 IP 地址。
4. **其他玩家**：浏览器输入房主的局域网 IP 地址（如 `http://192.168.1.5:3000`）加入。

### 方式 2: 服务器部署 (推荐用于多人联机)

**使用 Docker (最简单，无需本地 npm)**
```bash
# 直接构建并启动（Docker 内部自动执行 npm install 和 npm run build）
docker-compose up -d

# 查看日志
docker-compose logs -f

# 更新代码后重新部署
docker-compose up -d --build

# 停止服务
docker-compose down
```

> 💡 多阶段构建，主机无需安装 Node.js 和 npm。

**使用 PM2 (传统方式)**
```bash
npm install
npm run build
npm install -g pm2
pm2 start dist/server/index.js --name guandan-game
pm2 save
```

📖 **完整部署指南**：参见 [DEPLOYMENT.md](./DEPLOYMENT.md)

### 方式 3: 开发运行
```bash
npm install
npm run dev           # 同时启动前端和后端
npm run build         # 构建产物到 dist/
npm run package       # 打包为可执行文件
```

## 📖 游戏规则 (Rules)

### 基础规则
- **牌型大小**：四大天王 > 同花顺 > 6+ 张炸弹 > 5 张炸弹 > 4 张炸弹 > 其他牌型。
- **级牌 (Level Card)**：当前打的等级牌（如打 2 时的所有 2）为级牌。
- **红心级牌 (Wild Card)**：红心级牌（如打 2 时的红桃 2）为**万能牌**，可代替任意牌。
- **三王炸**：任意 3 张王组成的炸弹（3 人模式最大炸弹）。

### 4 人模式（2v2）
- **双扣**：同队两人分别获第 1、2 名 → 下局升 3 级，对方进贡两张。
- **单扣**：同队分别获第 1、3 名 → 下局升 2 级，末游向头游进贡一张。
- **保级**：同队分别获第 1、4 名 → 下局升 1 级，末游向头游进贡一张。

### 3 人模式（争上游）
- 去掉一种花色，共 81 张牌，每人 27 张，无队友。
- **三王炸**为最大炸弹（取代四大天王）。
- 头游升 3 级、二游升 1 级、末游不升。
- 末游向头游进贡最大牌，头游还牌 ≤10。

### 对局流程
1. **开始对局**：房主选择游戏模式（普通/技能）与人数（3 人/4 人）并开始。
2. **多局游戏**：从 2 级开始，每局结束后根据胜负自动升级。
3. **对局结束**：某队（4 人）或某玩家（3 人）达到 A 级别并连胜 2 次，宣布获胜。
4. **返回大厅**：对局结束后所有玩家返回房间大厅。

### 技能模式特殊规则
- 每局开始时每位玩家随机获得 2 张技能卡。
- 技能卡只能在自己的回合使用，每张只能用一次。
- 使用技能后仍可正常出牌。
- 新获得的牌会高亮显示 2 秒。

## 🏗️ 架构设计

### Match-Game 双层架构
```
Room (房间)
  └── Match (完整对局，从2打到A)
       └── Game (单局游戏，直到一方出完)
            └── 多个回合 (Rounds)
```

### 复盘记录
- 每局通过 `gameRecorder.ts` 落盘完整 JSON（默认 `game-records/`，可用 `GUANDAN_RECORDS_DIR` 覆盖）。
- 记录初始手牌 + 全部事件（出牌/过牌/进贡/技能），出牌事件含该手剩余手牌，可还原任意时刻牌面。

### 技能系统设计
- **95%+ 代码共享**：普通模式和技能模式共享所有核心游戏逻辑。
- **插件式架构**：技能系统作为可选模块叠加在核心逻辑之上。
- **生命周期管理**：游戏实例具有完整生命周期（创建、运行、销毁），防止旧游戏状态污染新游戏。
