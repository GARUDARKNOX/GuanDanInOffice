# 三人掼蛋模式 - 详细改动清单

> 文档版本：v1.0
> 项目：GuanDanInOffice-master（TypeScript + React + Socket.IO）
> 目标：在现有4人掼蛋基础上，新增3人掼蛋模式（各打各的，争上游）
> 原则：复用现有牌型/规则引擎，最小侵入式改动，4人模式保持不变

---

## 一、三人掼蛋规则要点（实现依据）

| 维度 | 4人模式（现有） | 3人模式（新增） |
|------|----------------|----------------|
| 牌数 | 两副108张 | 两副去掉一种花色(梅花♣)26张 + 1张大王 = **81张** |
| 每人手牌 | 27张 | **27张** |
| 队伍 | 2v2（0,2队 / 1,3队） | **无队友，各打各的** |
| 胜负判定 | 头游/二游/三游/末游（队内配合） | 头游/二游/末游（争上游） |
| 最大炸弹 | 四大天王（2小+2大王） | **三王炸（任意3张王）**——4人规则的 FourKings 不适用 |
| 升级规则 | 双扣+3 / 单扣+2 / 保级+1（队级） | **头游+3 / 二游+1**（个人级） |
| 进贡 | 末游→头游，三游→二游（双扣时） | **末游→头游**（最大牌），头游还牌≤10 |
| 抗贡 | 双大王抗贡 | **双大王抗贡**（保留）或调整为三王抗贡（需确认） |
| 接风 | 队友走牌后接风 | **无接风**（无队友，头游的下家继续） |
| 级牌/逢人配 | 红心级牌为万能牌 | 保留（级牌仍为当前等级，红心级牌为万能牌） |
| 技能模式 | 可叠加 | 3人模式可叠加技能（可选，非必需） |

**待确认项**（实现时需询问产品）：
1. 去掉的花色固定为梅花♣，还是房主可选？
2. 三王炸的组成：任意3张王（2小+1大 或 1小+2大 或 3小 或 3大）？还是仅"2小+1大"和"1小+2大"？
3. 逢人配（万能牌）在3人模式是否保留？建议保留以维持一致性。
4. 抗贡条件：维持"双大王"还是改为"任意双王"？
5. 技能模式是否与3人模式兼容？建议首期仅支持普通模式3人。

## 三、逐文件改动清单

### 3.1 `src/shared/types.ts`（新增枚举）

**目标**：引入玩家模式枚举，供全栈识别3人/4人。

**具体改动点**：

1. **新增 PlayerMode 枚举**（在 `GameMode` 枚举附近）：
   ```ts
   export enum PlayerMode {
     Four = 4,   // 4人模式（现有）
     Three = 3   // 3人模式（新增）
   }
   ```

2. **新增 HandType 枚举值**：
   - 现有：`FourKings = 'FourKings'`（四大天王，2小+2大）
   - 新增：`ThreeKings = 'ThreeKings'`（三王炸，任意3张王）
   - **注意**：`FourKings` 在3人模式不会出现（牌池只有3张王），但4人模式保留不动。

3. **可选**：在 `Card` 接口无需改动；在 `HistoryEntry` 的 `details` 已是 `any`，无需改。

**影响范围**：types.ts 是全栈共享，改动向后兼容（仅新增枚举值）。

### 3.2 `src/shared/deck.ts`（新增3人发牌）

**目标**：支持生成81张牌的3人牌堆。

**具体改动点**：

1. **保留** `createDeck()`（108张，4人用）不动。

2. **新增** `createDeck3P(): Card[]` 函数：
   - 基础两副牌（108张）
   - **去掉所有 `Suit.Clubs`（梅花）的牌**：26张 × 2副 = 52张 → 移除
   - **去掉1张大王**：2张大王 → 移除1张
   - 结果：108 - 52 - 1 = **55张**？❌ 不对
   - 修正计算：两副牌中梅花有 13×2=26张，去掉后剩 108-26=82张；再去1张大王 = **81张** ✓
   - 每张牌的 `id` 需保持唯一（现有 id 格式 `${suit}-${rank}-${i}`，移除后无冲突）

3. **可选**：新增 `createDeck(playerMode: PlayerMode): Card[]` 重载，内部根据模式分发。推荐保留两个独立函数（`createDeck` 和 `createDeck3P`）以保持向后兼容。

4. **`shuffleDeck`、`updateCardProperties` 无需改动**（与牌数无关）。

**验证点**：
- 3人模式发牌后 `deck.length === 81`
- 每人 `27` 张
- 牌堆中无 `Suit.Clubs`，大王只有1张，小王2张

### 3.3 `src/shared/rules.ts`（新增三王炸）

**目标**：识别"任意3张王"为三王炸，并参与比较。

**具体改动点**：

1. **`getHandType()` 函数**（约第110行起）：
   - 在现有 `FourKings` 检测（第129-135行）之前或之后，新增 `ThreeKings` 检测：
     ```ts
     // 3张王 = 三王炸（3人模式）
     if (len === 3) {
       const jokers = cards.filter(c => c.rank === Rank.SmallJoker || c.rank === Rank.BigJoker);
       if (jokers.length === 3) {
         return { type: HandType.ThreeKings, cards, value: 998 }; // 低于 FourKings(999)
       }
     }
     ```
   - **注意**：现有3张牌逻辑（第156-162行 `Trips`）会先检测 `uniqueValues.length === 1`，王的 uniqueValues 不唯一（SmallJoker=15, BigJoker=16），所以不会误判为 Trips。但为安全起见，三王炸检测应放在 Trips 检测之前。

2. **`compareHands()` 函数**（约第254行）：
   - 新增 `ThreeKings` 的比较规则：
     ```ts
     if (handA.type === HandType.ThreeKings) {
       // 三王炸大于所有普通牌和炸弹，但小于四大天王
       if (handB.type === HandType.FourKings) return -1;
       return 1;
     }
     if (handB.type === HandType.ThreeKings) {
       if (handA.type === HandType.FourKings) return 1;
       return -1;
     }
     ```
   - 插入位置：在现有 `FourKings` 判断（第255-256行）之后。

3. **`getHandDescription()` 函数**（约第292行）：
   - 在 `typeNames` 映射中新增：`[HandType.ThreeKings]: '三王炸'`

4. **`getAllPossibleHandTypes()` 函数**（约第320行）：
   - 3张王的场景：直接返回 `{ type: HandType.ThreeKings, cards, value: 998 }`（无需多解释）

**验证点**：
- `[小王, 小王, 大王]` → ThreeKings
- `[小王, 大王, 大王]` → ThreeKings（3人模式只有1张大王，此组合不存在于3人；但4人模式也不应误判）
- 3人模式中 `[小王, 小王]`（2张）→ 仍是 Pair（对王），不触发 ThreeKings
- 三王炸 > 6张炸弹 > 5张炸弹 > 同花顺 > 普通牌

**注意**：3人模式牌池只有2小王+1大王=3张王，三王炸必然是 `[小王,小王,大王]` 这唯一组合。但代码应兼容任意3王组合以应对4人模式（4人模式不会触发，因为 FourKings 优先）。

### 3.4 `src/shared/bot.ts`（Bot 3人逻辑）⚠️ 大改

**目标**：Bot 在3人模式下无队友概念，纯个人争上游策略。

**具体改动点**：

1. **构造函数**（第960行）：
   - 新增可选参数 `playerMode: PlayerMode = PlayerMode.Four`
   - 存储 `this.playerMode`
   - `handsInfo` 长度可能为3（而非4）

2. **`isAlly()` 方法**（第969行）：
   ```ts
   private isAlly(idx: number): boolean {
     if (this.playerMode === PlayerMode.Three) return false; // 3人无队友
     return idx >= 0 && idx % 2 === this.seatIndex % 2;
   }
   ```

3. **`partnerIdx()` 方法**（第973行）：
   - 3人模式返回 -1（无队友）
   ```ts
   private partnerIdx(): number {
     if (this.playerMode === PlayerMode.Three) return -1;
     return (this.seatIndex + 2) % 4;
   }
   ```

4. **`nextEnemyHasOne()` / `nextEnemyDanger()`**（第985、991行）：
   - `(this.seatIndex + 1) % 4` → `(this.seatIndex + 1) % this.playerMode`
   - 3人模式：`% 3`

5. **`allyNearOut()`**（第997行）：
   - 3人模式直接返回 false（无队友）

6. **`decideFollowPlay()` 中的队友逻辑**（约第1532-1565行）：
   - 所有 `if (lastPlayerIndex === partner)` 分支：3人模式下跳过（`partner === -1` 自然不匹配，但建议显式 `if (this.playerMode === PlayerMode.Three) {/* 无队友分支 */}`）
   - 第1565行 "上家是队友（非对门），不压"：3人模式下删除此规则，上家是敌人就该考虑压牌

7. **`decideFreePlay()` 中的角色定位**（约第1077-1080行）：
   - `getRole()` 返回 'attacker'/'supporter'：3人模式恒为 'attacker'
   - 不再有"送队友"策略

8. **回合推进 `% 4` → `% playerCount`**：
   - 全文搜索 `% 4` 在 bot.ts 中的出现（第974、986、992、1570、1576、1577行等）
   - 全部替换为 `% this.playerMode`（注意 playerMode 是数字3或4）

   - `TOTAL_PER_RANK` 假设8张（2副×4花色）。3人模式去掉梅花后，每rank只有6张（2副×3花色）。
   - 需让 `CardTracker` 接收 `playerMode` 参数，动态计算 total：
     ```ts
     const suitsPerRank = playerMode === 3 ? 3 : 4;
     TOTAL_PER_RANK[r] = 2 * suitsPerRank; // 6 或 8
     TOTAL_PER_RANK[15] = 2; // 小王2张（不变）
     TOTAL_PER_RANK[16] = playerMode === 3 ? 1 : 2; // 大王：3人1张，4人2张
     ```
   - 影响 `getRemaining()`、`couldHaveBomb()` 的判断基准

10. **炸弹阈值调整**：
    - `couldHaveBomb(rank)`: 4人模式 `>= 4`，3人模式可考虑 `>= 4`（6张池仍可能凑4张同rank炸弹）——保持4不变
    - 三王炸的识别：Bot 在3人模式应意识到3张王是最大炸弹

**验证点**：
- 3人模式 Bot 不会尝试"送队友"
- Bot 在3人模式会考虑压制所有其他玩家
- CardTracker 在3人模式正确报告剩余牌数

## 五、风险点与注意事项

### 5.1 高风险

1. **`teamLevels` 数据结构变更**：4人用 `{0:2, 1:2}`，3人用 `{0:2, 1:2, 2:2}`。若统一字段，需确保4人逻辑不破坏。
   - **建议**：引入新字段 `levelMap: { [key: number]: number }`，4人模式 key=team(0/1)，3人模式 key=seat(0/1/2)。客户端按 playerMode 解释。

2. **`% 4` 硬编码遍布全代码**：game.ts、bot.ts、GameTable.tsx 大量 `% 4`。遗漏一处会导致3人模式回合错乱。
   - **建议**：全局搜索 `% 4`，逐一审查。

3. **进贡逻辑分叉**：4人双扣/单扣/抗贡 vs 3人单一进贡。建议拆分为两个独立方法，避免条件嵌套过深。

4. **抗贡条件**：3人模式只有1张大王，"双大王抗贡"不可能。需产品确认替代规则。

### 5.2 中风险

5. **Bot 策略退化**：3人模式 Bot 失去队友配合逻辑后，可能表现呆板。需调整争上游策略（更激进抢头游）。

6. **CardTracker 牌池基准**：3人模式每rank只有6张（非8张），`couldHaveBomb` 阈值需复核。

7. **接风移除**：3人模式头游走牌后，下家直接出牌。需确保 `endRoundAndFindNext` 不误触发接风。

### 5.3 低风险

8. **UI 布局**：3人三角形座位，CSS 调整量中等。

9. **技能模式兼容**：3人+技能组合首期可不支持，强制 `playerMode===Three && gameMode===Skill` 时提示"暂不支持"。
